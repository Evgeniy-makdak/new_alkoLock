# Алкозамок-М SMART. Frontend

Frontend-приложение информационной системы «Алкозамок-М SMART».

Проект используется в нескольких вариантах поставки:

- web-версия в браузере;
- PWA/мобильная браузерная версия;
- desktop-клиент на Electron для Windows и macOS.

Все варианты используют один и тот же frontend-код. Electron не содержит отдельную копию бизнес-логики: это desktop-оболочка, которая открывает тот же web-сервер и добавляет нативное поведение для окна чата.

## Руководство администратора сети и развёртывания

Этот раздел предназначен для сетевого администратора, DevOps-инженера или специалиста, который разворачивает систему на сервере и устанавливает desktop-клиент на рабочие места операторов.

### Обзор: как устроена система

Система состоит из **двух независимых контуров поставки**:

| Контур | Что входит | Где работает | Как обновляется |
|--------|------------|--------------|-----------------|
| **Серверный** | Статика frontend (`build/`), Java backend, Nginx | Docker на сервере (Linux) | Деплой Docker-образа / обновление `build/` на сервере |
| **Клиентский (desktop)** | Установщик Electron (`.exe` / `.dmg`) | ПК оператора (Windows / macOS) | Раздача нового установщика; пересборка нужна только при изменении desktop-оболочки |

**Важно:** desktop-клиент **не является автономным офлайн-приложением**. Внутри `.exe` / `.dmg` нет копии React-приложения — только оболочка Chromium (Electron). При запуске клиент подключается к вашему серверу по HTTPS и загружает интерфейс так же, как браузер.

```text
┌──────────────────────────────────────────────────────────────────────┐
│  ПК оператора                                                        │
│                                                                      │
│   Браузер ──────────┐                                                │
│                     ├──►  https://alcolock.company.ru  ──►  Nginx    │
│   Electron (.exe) ──┘         (тот же URL)              │          │
└───────────────────────────────────────────────────────────┼──────────┘
                                                            │
┌───────────────────────────────────────────────────────────┼──────────┐
│  Сервер (Docker)                                          ▼          │
│                                                                      │
│   Nginx ──► отдаёт статику из build/ (HTML, JS, CSS)                 │
│         ──► проксирует REST API ──────────────► Java backend         │
│         ──► проксирует WebSocket /ws/websocket ► Java backend        │
│         ──► отдаёт /config.json (адреса API и WebSocket)             │
└──────────────────────────────────────────────────────────────────────┘
```

Для Nginx **не требуется отдельная конфигурация под Electron**. Desktop-клиент обращается к серверу теми же HTTP(S)-запросами, что и браузер.

### Серверная часть: развёртывание через Docker

Серверный контур **не меняется** при добавлении desktop-клиента. Существующий пайплайн сборки frontend остаётся прежним.

Каталог `docker-build/` содержит скрипты для сборки web-версии внутри Docker-контейнера:

```bash
# На билд-машине (Linux)
cd docker-build
./build.sh
```

Скрипт `docker-entrypoint.sh` выполняет `yarn install` и `yarn build`, результат — папка `build/` со статикой frontend.

Далее `build/` вместе с Java backend и конфигурацией Nginx упаковывается в Docker-образ и разворачивается на сервере **так же, как до появления Electron**. Точная схема orchestration (docker-compose, Kubernetes и т.д.) зависит от вашей инфраструктуры и описывается в документации backend-проекта.

**Electron в Docker-контейнер на сервере не устанавливается и не запускается.**

### Настройка runtime-конфига (`config.json`)

После сборки frontend в папке `build/` появляется файл `config.json`. И браузер, и Electron читают его **с сервера** при каждом запуске приложения.

Шаблон (файл `public/config.json` в исходниках):

```json
{
  "apiUrl": "https://{DOMAIN}/",
  "wsUrl": "wss://{DOMAIN}/ws/websocket"
}
```

**Для production** замените `{DOMAIN}` на реальный домен или укажите полные URL:

```json
{
  "apiUrl": "https://alcolock.company.ru/",
  "wsUrl": "wss://alcolock.company.ru/ws/websocket"
}
```

Плейсхолдер `{DOMAIN}` позволяет не менять исходники при переносе между стендами — достаточно подставить домен на этапе деплоя (через CI, sed, шаблонизатор Nginx и т.п.).

**Администратору важно:**

- `apiUrl` и `wsUrl` должны указывать на тот же Nginx, через который отдаётся frontend (единая точка входа).
- Путь WebSocket (`/ws/websocket`) должен совпадать с настройкой проксирования в Nginx и backend.
- Файл `config.json` можно менять на сервере **без пересборки** frontend — клиенты подхватят новые значения при следующем запуске.

### Требования к сети и инфраструктуре

#### DNS и HTTPS

- Зарегистрируйте DNS-имя, например `alcolock.company.ru`, указывающее на сервер с Nginx.
- Обязателен **валидный TLS-сертификат** (Let's Encrypt, корпоративный CA). Electron и браузеры отклоняют самоподписанные сертификаты без явного доверия в ОС.
- Desktop-клиент при первом запуске запрашивает у оператора **только URL frontend**, например `https://alcolock.company.ru`. Отдельно вводить `apiUrl` / `wsUrl` не нужно.

#### Firewall и прокси

С рабочих мест операторов до сервера должны быть открыты:

| Направление | Протокол | Порт | Назначение |
|-------------|----------|------|------------|
| ПК оператора → сервер | HTTPS (TCP) | 443 | Загрузка интерфейса, REST API |
| ПК оператора → сервер | WSS (TCP) | 443 | WebSocket чата (через тот же Nginx) |

Если в организации используется корпоративный HTTP-прокси с SSL-инспекцией, убедитесь, что домен приложения не ломается MITM-проверкой, либо добавьте корневой сертификат прокси в доверенные на ПК операторов.

#### VPN

Если сервер доступен только из корпоративной сети или VPN, операторы должны быть подключены к VPN **до** запуска desktop-клиента или браузера.

### Desktop-клиент: что раздавать операторам

Desktop-артефакты собираются **отдельно** от Docker-образа сервера и распространяются через внутреннее хранилище (файловый сервер, портал ПО, GitHub Releases, артефакты CI).

#### Windows

| Файл | Назначение | Ярлык на рабочем столе |
|------|------------|------------------------|
| `Alcolocks Operator Setup-<версия>-x64.exe` | **Установщик (рекомендуется)** | Да, создаётся автоматически |
| `Alcolocks Operator-<версия>-portable-x64.exe` | Portable, без установки | Нет |
| `win-unpacked/` | Распакованные файлы (для отладки) | Нет |

**Для массовой установки на рабочие места используйте файл `… Setup-….exe`**, а не portable и не `win-unpacked/Alcolocks Operator.exe`.

Установщик можно развернуть:

- вручную на каждом ПК;
- через групповые политики (GPO), SCCM, Intune или аналог — тихая установка NSIS поддерживается стандартными ключами `/S` (проверьте на тестовом ПК).

#### macOS

| Файл | Назначение |
|------|------------|
| `Alcolocks Operator-<версия>-x64.dmg` | Установка на Intel Mac |
| `Alcolocks Operator-<версия>-arm64.dmg` | Установка на Apple Silicon |

Оператор перетаскивает приложение из `.dmg` в папку «Программы». Для production рекомендуется подпись Apple Developer ID и notarization — иначе Gatekeeper может блокировать запуск.

#### Linux desktop

Отдельная сборка Electron для Linux (AppImage, `.deb`) **в текущей конфигурации проекта не предусмотрена**. Она понадобится только если операторы работают за Linux-десктопом. Сервер при этом может спокойно работать на Linux в Docker — это не связано с ОС рабочего места.

### Установка desktop-клиента на рабочем месте (пошагово)

#### Windows

1. Скачайте `Alcolocks Operator Setup-<версия>-x64.exe` с внутреннего портала раздачи ПО.
2. Запустите установщик от имени пользователя (права администратора обычно не требуются для установки в профиль пользователя).
3. Пройдите мастер установки. На рабочем столе появится ярлык **«Alcolocks Operator»**.
4. Запустите приложение. При **первом** запуске откроется окно «Введите адрес сервера».
5. Введите URL frontend, например `https://alcolock.company.ru`, нажмите «Подключиться».
6. Откроется страница авторизации. Дальнейшая работа — как в браузере.

Адрес сервера сохраняется локально в профиле пользователя Windows (`%APPDATA%\alcolocks-operator-desktop\` или аналог в `userData` Electron). При следующих запусках окно ввода адреса не показывается.

**Смена сервера:** меню **Alcolocks Operator → Сменить сервер**.

#### macOS

1. Откройте `.dmg`, перетащите «Alcolocks Operator» в «Программы».
2. Запустите приложение (при первом запуске подтвердите в Gatekeeper, если нет подписи).
3. Введите адрес сервера — далее как на Windows.

### Сборка артефактов на билд-машине / CI

Рекомендуется **три независимых job** в CI:

```text
Job 1 (Linux)     →  docker-build/build.sh  →  Docker-образ сервера (web + backend)
Job 2 (Windows)   →  yarn electron:setup:win →  Setup.exe для операторов
Job 3 (macOS)     →  yarn electron:dist:mac  →  .dmg для операторов
```

Команды для desktop-сборки (подробности — в разделах ниже):

```powershell
# Windows-агент
yarn install
yarn electron:setup:win
```

```bash
# macOS-агент
yarn install
yarn electron:dist:mac
```

**`yarn build` перед сборкой Electron не обязателен** — React-приложение не вшивается в `.exe`. Desktop-оболочка загружает UI с сервера.

Готовые файлы появляются в `release/`. **Не коммитьте `release/` в git** — артефакты большие (GitHub отклоняет файлы > 100 MB). Храните их в артефактах CI или на файловом сервере.

### Обновление системы

| Что изменилось | Действие администратора |
|----------------|-------------------------|
| Логика frontend (`src/`), UI, API-вызовы | Деплой нового `build/` / Docker-образа на сервер. **Пересборка `.exe` не нужна** — операторы получат обновление при следующем запуске клиента |
| `config.json` (адреса API, WebSocket) | Обновить файл на сервере. Пересборка не нужна |
| Desktop-оболочка (`electron/`), installer, меню | Собрать новый Setup.exe / .dmg и раздать операторам |
| Java backend | Деплой backend по процедуре backend-проекта. Frontend и Electron обычно не пересобираются |

### Предустановка адреса сервера (опционально)

Для корпоративного развёртывания можно заранее зашить URL сервера в сборку. Файл `electron/app.config.json`:

```json
{
  "appUrl": "https://alcolock.company.ru/authorization"
}
```

Этот файл копируется в ресурсы установщика (`extraResources` в `electron-builder.json`). Он используется как значение по умолчанию в окне первого запуска. Оператор всё равно может сменить сервер через меню.

Альтернатива для автоматизации: переменная окружения `ELECTRON_APP_URL` или аргумент командной строки `--app-url=https://…` (для тестирования и тонкой настройки).

### Диагностика проблем

| Симптом | Возможная причина | Что проверить |
|---------|-------------------|---------------|
| Белый экран / «не удаётся открыть страницу» | Нет сети, неверный URL, блокировка firewall | `ping` / `curl https://домен/authorization` с ПК оператора |
| Ошибка сертификата | Самоподписанный или просроченный TLS | Сертификат Nginx, доверие CA на ПК |
| Авторизация есть, API не работает | Неверный `config.json`, Nginx не проксирует `/api` | `curl https://домен/config.json`, логи Nginx и Java |
| Чат не подключается | WebSocket не проксируется | `wss://домен/ws/websocket`, заголовки `Upgrade` / `Connection` в Nginx |
| Desktop не обновился после деплоя frontend | Кэш (редко) | Перезапуск клиента; в dev — hard refresh; на сервере — актуальный `build/` |
| Нет ярлыка на рабочем столе | Установлен portable, а не Setup | Переустановить через `… Setup-….exe` |

Логи Electron на Windows можно смотреть, запустив приложение из командной строки — в консоль выводятся строки вида `[electron] loading main window: …`.

### Чек-лист администратора перед вводом в эксплуатацию

- [ ] DNS-имя указывает на сервер с Nginx
- [ ] TLS-сертификат валиден для всех клиентов
- [ ] `build/` развёрнут, `https://домен/` открывается в браузере
- [ ] `https://домен/config.json` возвращает корректные `apiUrl` и `wsUrl`
- [ ] REST API и WebSocket работают через Nginx (проверка из браузера и с ПК оператора)
- [ ] Firewall пропускает HTTPS (443) с рабочих мест до сервера
- [ ] Setup.exe / .dmg размещены на портале раздачи ПО
- [ ] Операторам передана инструкция: URL сервера для первого запуска
- [ ] (Опционально) В `electron/app.config.json` при сборке указан production-URL

Запуск web-приложения в режиме разработки:

```bash
yarn start
```

```text

```

```bash
yarn electron:dev
```

Эта команда одновременно запускает dev-сервер React и Electron-оболочку.

Сборка обычной web/PWA-версии:

```bash
yarn build
```

Результат появляется в папке:

```text
build/
```

Папка `build/` не хранится в git. Это артефакт сборки.

### Runtime-Конфиг

В web-сборке используется runtime-файл:

```text
build/config.json
```

Пример:

```json
{
  "apiUrl": "https://{DOMAIN}/",
  "wsUrl": "wss://{DOMAIN}/ws/websocket"
}
```

`apiUrl` и `wsUrl` читаются приложением во время запуска. Это позволяет менять backend/websocket-адрес без пересборки frontend-кода.

Если вместо `{DOMAIN}` указан конкретный адрес, приложение будет использовать его как есть:

```json
{
  "apiUrl": "https://alcolock-test.lsystems.ru/",
  "wsUrl": "wss://alcolock-test.lsystems.ru/ws/websocket"
}
```

## Electron Desktop-Клиент

Electron используется для desktop-версии приложения.

Что даёт Electron:

- отдельное desktop-окно приложения;
- frameless/transparent detached-окно чата;
- отключение системных кнопок у detached-окна чата;
- перемещение detached-чата между мониторами;
- единый desktop-клиент для работы с тем же сервером, что и браузерная версия.

### Первый Запуск

При первом запуске desktop-клиент показывает окно:

```text
Введите адрес сервера
[ https://server-company.ru ]
[ Подключиться ]
```

Пользователь вводит только frontend-адрес сервера, например:

```text
https://alcolock-test.lsystems.ru
```

Electron сохраняет адрес локально в профиле пользователя и дальше открывает приложение автоматически.

`apiUrl` и `wsUrl` отдельно в Electron указывать не нужно. После открытия сайта React-приложение само читает обычный `/config.json` с выбранного сервера.

### Смена Сервера

Если нужно сменить сервер, используйте меню desktop-приложения:

```text
Alcolocks Operator -> Сменить сервер
```

После этого Electron снова покажет окно ввода адреса сервера.

### Значение По Умолчанию

Файл:

```text
electron/app.config.json
```

используется как дефолтный fallback/пример адреса для Electron-сборки.

Пример:

```json
{
  "appUrl": "http://alcolock-test.lsystems.ru/authorization"
}
```

Для обычного пользователя предпочтительный сценарий: ввести адрес сервера при первом запуске.

## Что Хранится в Git

В git хранятся исходники и конфигурация:

- `src/`
- `public/`
- `electron/`
- `electron-builder.json`
- `package.json`
- `yarn.lock`

В git не хранятся артефакты сборки:

- `build/`
- `release/`
- `node_modules/`
- `electron/node_modules/`

Если нужно передавать готовые `.exe` или `.dmg`, используйте:

- GitHub Releases;
- CI artifacts;
- внутреннее файловое хранилище;
- сервер загрузок.

Не добавляйте `release/` в git: Electron-артефакты большие, GitHub отклоняет файлы больше 100 MB.

## Архитектура

Проект использует подход Feature-Sliced Design.

Основные слои и сегменты:

- `app` - инициализация приложения, глобальные провайдеры, layout;
- `pages` - страницы приложения;
- `widgets` - крупные самостоятельные блоки интерфейса;
- `features` - пользовательские сценарии и действия;
- `entities` - бизнес-сущности;
- `shared` - общие компоненты, API-клиенты, утилиты, конфигурация.

Внутри слайсов могут использоваться сегменты:

- `ui` - компоненты;
- `model` - состояние;
- `api` - запросы и API-адаптеры;
- `lib` - вспомогательная логика;
- `hooks` - React hooks;
- `config` - константы и конфигурация.

## Важные Замечания

- Web, PWA и Electron используют один frontend-код.
- Изменения в `src/` попадают в браузер/PWA после обычного `yarn build` и деплоя на сервер.
- Electron-клиент, который открывает этот сервер, увидит те же изменения без пересборки `.exe/.dmg`.
- Пересобирать Electron нужно только при изменении самой desktop-оболочки: `electron/`, `electron-builder.json`, desktop-меню, native-window поведение, installer-настройки.
- Windows `.exe` не запускается на macOS. Для macOS собирается отдельный `.dmg`.
